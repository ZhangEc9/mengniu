# 导轨优先几何实验：过程记录与经验总结

时间：2026-09-30。本文汇总本轮"自动找导轨走廊 + 复用已验证找框"实验的对话要点、思路演变、踩过的坑和下一步。交接时请与《密集价签识别测试现状与下一步.md》一起读。

## 一、本轮做了什么

用户补标了 6 张人工图（`新数据/`，LabelMe 格式：`rectangle`=价签框带价格与 tag_type，`rotation "框"`=导轨走廊框，斜排带 direction），要求开始文档里第 2、3 步的实验。产出：

- `rail_first_experiment.py`：主实验脚本（阶段 A 自动找走廊 + 阶段 B 复用已验证找框 + 段集评测 + 叠图）
- `analyze_rows.py`：真排/假排特征对比（选排级门槛用）
- `summarize_new_labels.py`、`diag_rails.py`、`debug_*.py`：数据检查与调试脚本
- 输出目录 `导轨优先几何实验/`：每图 overlay.jpg、rails.json、summary.json、特征报表

## 二、方案演变（重要，别重复走过的弯路）

1. **Hough 线段配对上下边（弃用）**。按文档直觉先找"导轨实体边对"，实测发现：人工导轨是低对比深色塑料，**没有强线**；反而是价签排自身上下沿是最强线（45566458 调试：导轨边 y=362/493 无强线，价签沿 support 3106/2133）。线段配对产生大量嵌套假走廊，且"每行取最外沿""取 support 最高"等启发式修一个破一个。
2. **实体排聚类（现行方案）**。反转思路：不找导轨线，直接全图多阈值轮廓找"价签样实体"（宽尺寸范围保召回）→ 按 y 中心聚类成排 → 排内实体中心拟合方向线（残差剔除）→ 链式合并被倾斜拆开的段 → 单实体吸收弥合断链 → 由排构造走廊。**走廊只是手段，价签框才是目的**——段不必合成完整长导轨，评估也改成"段集"口径（人工排附近所有段的并集）。
3. **双走廊解耦**。评测要走廊罩得住价签（宽，每侧 +0.5×实体高），检测要走廊贴着价签（紧，+0.15，几何等价已验证的人工 rail_top/bottom=93/160）。一个走廊满足不了两个需求，分开建。
4. **排级门槛**。真排/假排特征对比（63 真排 vs 130 假排）显示单一几何特征基本不可分；`bot_edge_sup`（排底边线下方 0-12px 的 Canny 命中率）最好：真排 p10≈0.43 vs 假排 p50≈0.53，取 0.45 保约九成真排砍近半假排。**残留商品排走廊不追求几何赶尽**——按文档设计，语义区分交给后续按 ID 的 API 类别门禁（tag/promo/package/empty），本地几何只管保召回。

## 三、遇到的问题与修复（按代价排序）

1. **cv2.warpAffine 矩阵方向语义（代价最大的一个 bug）**。默认 M 是**前向映射（src→dst）**，函数内部自己求逆采样；我一直按 dst→src 构造并平移，被二次求逆后采样错位——先是裁块横向错位 930px（右半取到图像外 replicate 出白带），后是整幅竖条纹。正确写法：`getRotationMatrix2D((cx,cy), angle, 1)` 后把中心平移到裁块内 `(u_c, v_c)`，`u_c = cx-(x0-CROP_PAD_X)`，`v_c = ch/2`。**修复后开发图 IoU0.3 命中 30→56、IoU0.5 25→49。**教训：图形 API 的矩阵方向必须用"采样几个点打印对应坐标"数值验证，不能靠推导。
2. **atan2 未归一化**。右→左线段的 atan2 = ±180°，导致：Hough 一半线段被当斜线丢弃；人工导轨框上下边被算成 176°，竖直侧边（90°）反而"最水平"胜出（user_angle=90° 的来源）。修复：统一 `normalize_angle_deg` 到 [-90,90)，比较时取绝对值。
3. **全局倾角投票（弃用）**。为解斜排 45524464（5.2°）引入，但包装文字实体太多，投票被带偏，直图从 5/5 掉到 1/5。换成"每段都拟合（不设门槛）→ 链式合并相容段 → 最后统一过滤"。
4. **倾斜拆段 + 单实体断链**。2° 在 1900px 上是 70px 漂移，y 聚类把一条排拆成小段，单实体段被 fit_row（需 ≥2 点）丢弃后链条断裂。修复：把落在段延长线 ±tol 内的散点吸收进段再合并。
5. **走廊越宽 containment 越好但检测越差**的跷跷板（见二.3，双走廊解决）。
6. 相对尺寸过滤换算：`TAG_H_REL` 上限 0.92×76px 会滤掉 78px 的真价签——**冻结的相对参数必须回到"已验证绝对值 ÷ 实际走廊高"反推校验**。
7. cv2 5.0 的 `HoughLinesP` 返回 (N,4) 而非 (N,1,4)；Windows 中文路径要用 `cv2.imdecode/imencode`（已验证代码里现成）。

## 五、经验教训

1. **先数值验证，再调参数**。本轮最大的两个坑（atan2 方向、warpAffine 语义）都不是参数问题，是 API 语义问题；靠"打印对应坐标/矩阵数值"各几分钟就能定位，靠调参耗掉数轮。
2. **每次只改一个变量**。走廊余量 0.35→0.5→0.15 来回振荡，是因为同时动了尺寸过滤——后来拆成双走廊才收敛。
3. **和已验证实现逐框对照是最快的定位手段**。`debug_stageB.py`（旧框/新框/GT 三方对照）一次就暴露了裁块偏移。
4. **文档里的判断持续得到验证**："导轨不是类别证明"（几何特征真/假排几乎不可分）、"普通流程始终是保底"、"语义排除靠 API 类别门禁"。
5. 人工标注质量很高但**只有用起来才知道口径**：rotation 框顶点顺序不定、direction 字段是弧度（2π 环绕）、29 个价签没填 tag_type（label 都是价格文本，按价签计入）。

## 六、下一步（按优先级）

1. **阶段 B 召回对齐已验证水平**：开发图顶排应复现 17/17。现在 preds 偏多、IoU0.5 49/86，逐排对照找剩余差距（怀疑：紧走廊中心取实体中心而非价签带中心，顶部贴边裁切）。
2. **斜排 45524464 攻坚**：段集采样判定仍未让斜排段入选（0/2），优先查链式合并后的角度/位置相容参数。
3. **preds 精度**：w/h 比例上限与 `bot_edge_sup` 门槛已收紧一轮，剩余虚警留给后续按 ID API 的类别门禁验证（本轮未接 API）。
4. 全部通过后，固定参数跑留出图盲测（文档第 4 步），再谈路由阈值。

## 发现的问题

1. **顶部导轨整排漏检**：正式放大版对顶部 17 个标注框（原图 y < 250）没有预测。80 个预测框主要来自下方导轨，数量接近 78 个标注框不等于识别完整。
2. **框和价格没有可靠绑定**：放大版有 37 个定位命中，但仅 16 个价格正确，即 21 个定位命中框读价错误。常见例子包括预测 4.80 / 标注 4.90、8.80 / 8.90、5.00 / 5.90；可视化中还出现沿整排均匀铺设、与真实价签错位的网格框。
3. **高置信度不能替代校验**：放大版 43 个框在 IoU 0.5 下未命中，其中 35 个预测置信度仍 ≥ 0.9。43 个未命中框中，3 个与某个标注框 IoU ≥ 0.5（但一对一匹配已被其他框占用），21 个的最佳 IoU 为 0.3–0.5，19 个低于 0.3；既有重复/偏移，也有较明显的错误定位。
4. **顶部单独裁切也不稳定**：2026-09-23 将原图 y=0–220 单独裁切并放大 2 倍，得到 16 个预测框，顶部 17 个标注仅定位命中 5 个，价格正确 0 个。原始返回与可视化见 `顶部导轨单独放大测试/top_0_220_x2.api.json` 和 `top_0_220_x2_vis.jpg`。
5. **旧缓存只能用于诊断，不能选优报分**：`密集条带复检结果/scale_debug/strip00_x2.json` 的一次顶部条带调用曾对顶部命中 13/17、价格正确 8 个；对应图与正式放大运行的图尺寸相同、像素平均差约 0.82，但文件并不完全一致，且旧缓存未记录全部调用条件。另一次关闭过滤的普通条带缓存对顶部命中 6/17、价格正确 0 个。不能用其中最好的一次代替正式完整评测；需记录输入与参数并复测稳定性。

## 第二步进展：实体边缘找框 + Qwen3-VL-Plus 局部读价（2026-09-23）

- `top_rail_slot_experiment.py` 在原图顶部目视选定的导轨区域 y=93–160 上做自适应阈值、轮廓候选和去重，**不使用 GT 生成框，不按等间距补框**。单阈值给出 16 框，IoU≥0.5 对顶部 17 个 GT 命中 14 个；多阈值补充独立边缘后给出 19 框，命中 17/17，顶部命中率 17/19=89.5%。候选框、漏检明细、叠框图分别在 `顶部导轨物理找框实验/` 和 `顶部导轨多阈值找框实验/`。后者有两个未匹配候选，不能直接全部入库。
- `probe_slot_prices.py` 仅调用项目现有 AISM 价签 API（用户补充实际模型为 Qwen3-VL-Plus），不换模型；只让它对**单个真实边缘候选的 crop 读价格**，不要求重新输出 bbox。所有原始响应和裁剪图片留痕，GT 价格只用于事后评测。16 个初始候选统一试了三种视图：常规小留白 2.2 倍、紧裁 3 倍、右上价格区 4 倍。14 个定位命中框中，单次正确读价分别为 7、9、7；第三种还有一次 API 连接超时，不能把它当作识别拒绝。

- 多阈值新增的三个定位框用紧裁 3 倍读价，两个价格与 GT 一致，一个错误。`assemble_dense_trial.py` 将 19 个顶部候选和原放大条带的 80 个下方候选离线组合，并用原评测脚本统一算 IoU≥0.5：**99 个预测框、54/78 定位命中（69.2%）、命中率 54.5%、27/78 价格正确（34.6%）**。相比原放大版 80 框、37/78 定位命中、16/78 价格正确，绝对增加 17 个定位命中、11 个价格正确；但总体错价、误检仍较多。报告见 `密集型多阈值组合实验/eval/summary.json`，逐框结果见同目录的 `gt_boxes.csv`、`predictions.csv`。
- **验证边界**：参数和 y 区间是在查看同一张图、同一份标注参考后开发的；该图上的 17/17 是开发集结果，不能算独立验收或跨门店泛化。融合只针对该图顶部补框，其他货架仍沿用旧结果；当前没有自动定位各导轨、没有价签可读性标注，也没有足以安全入库的价格拒识规则。

### 提示词、切条完整性与斜货架风险（2026-09-23）

- **提示词不同，不能把提升单独归因于找框**：旧条带调用使用 `prompts/price_system_prompt_final.txt` 和 `price_user_prompt_final.txt`，让 API 同时生成 `bbox` 和价格，看不清就跳过；`rail_numbered_read.py` 使用短的编号读价提示词，让模型对每个本地框 ID 返回 `price/readable`，看不清可返回 `null/false`，不生成 bbox。输入裁图、缩放和提示词同时改变，6/6 对 0/6 是组合方案对照，不是单变量消融。
- **当前“哪一条”仍由人指定**：红圈实验的 y=865–935、x=970–1665 是目视选定的范围。范围内 `top_rail_slot_experiment.py` 用自适应阈值轮廓提取候选，固定原图候选宽 45–115、高 30–65 像素并补少量边距；这不是自动导轨识别，也没有证明每个轮廓都覆盖完整实体价签。整排初始预览出现空框及重叠框，存在把一张价签切半或把两张价签混入同一框的风险。红圈区段的编号输入图经目视核查没有上下截断，但不能推广。
- **斜货架图像诊断**：`新数据/45524464_6_first_normal_1781829504624_12327780.jpeg` 的上层导轨用原图直线检测得到一条斜率约 0.105 的长边（[595,92]→[1918,231]），跨全宽相当于约 202 像素的高度变化；人工框只用于事后检查，顶部 10 框拟合斜率约 0.099。固定水平裁条明显可能从左右两端切掉价签。`整排编号一次读价实验/新数据斜货架_仅拉平预览.jpg` 仅展示按图像直线拉平后的一条视觉预览，**没有在该图完成自动找框或 API 读价，更不能称为泛化成功**。
- **拟定处理**：先从图像边缘估计各导轨上下界及倾斜/透视，沿导轨裁取足够余量并用仿射或透视变换拉平；再用实体边界找候选，检查候选是否触及裁条边界、严重相互重叠、覆盖多张或只有半张价签。不满足完整性检查时扩大范围重检或保留原 API/人工复核，不能硬输出价格。合格的整排候选编号后一次 API 读价，最后将框四角反变换回原图并按 IoU、价格与人工样本评测。透视明显变化时不能只用一条固定直线，应分段拟合或使用四边形变换。

## 当前判断

同一张图上，顶部实体边缘找框加局部读价比整条带自由生成 bbox 的定位和价格召回更高；但模型仍会稳定地把模糊价格读错。当前组合结果仅作为开发集实验，不应直接接入自动入库，也不应根据 VLM 置信度或多次一致性单独放行。

# 密集价签识别：现状、主线与下一步

更新时间：2026-09-28。本文是离线实验交接，不表示生产方案已经完成或通过泛化验证。

## 一句话结论

**继续沿用已经有效的组合方法，不用全图结构探针替换它。**普通照片保留原 Qwen3-VL-Plus API 识别；疑似密集的局部导轨先找真实上下边界和方向，在导轨走廊内沿用已有的多阈值轮廓找框，检查完整性，再将合格候选编号、整段一次提交 API 只读价格。找不到可靠导轨或完整框时回退原链路/人工复核，不等距补框，不让高置信度掩盖错位。

**当前已验证的只是开发图上的局部有效性，不是自动找导轨、更不是全图或跨店泛化。**以下所有比例须连同样本、区域、候选来源一起读。

## 数据边界与评测口径

- 开发图：images/45727462_6_first_normal_1782463362055_B04C0D8E.jpg；ground_truth/ 中 78 个位置和价签经用户人工核对。框位置可靠，少数小数模糊，故价格精确匹配与容差诊断分开报。
- 用户确认新数据/ 下的图像与 JSON 可作为人工新数据。目前有 5 组；其中 45035165… 的原始 JSON 是人工标注，**有价签_带框可视化图片不是人工真值**。其它图像/标注需按文件名配对，不能用可视化图代替 JSON。
- 定位指标默认人工框与预测框一对一匹配、IoU≥0.5；价格正确须先定位命中。另报 IoU 0.3/0.7、预测框命中率、漏检、重复、半框、合框。价差≤0.10 和“整数元相同”只作辅助诊断；后者会把 8.90 与 8.00 算同价，不可自动当精确读价正确。
- 离线找框不能读取 GT 位置、价格来生成候选或选择参数。人工标注仅用于事后评测；开发图可诊断，最终判断应在预先冻结参数的留出图进行。

## 问题一：怎样划分密集型

**先区分“照片/区域是否密集”与“该区域是否具备本地找框条件”。**货架、冰箱和促销场景都可能既有密集排又有普通区域，故路由宜以**价签排/局部区段**为单位，整图输出可为 normal、dense、mixed、uncertain。普通流程始终是默认保底，不要只凭“冰箱照”或“矩形多”全图改路由。

拟定离线可测定义（**假设，未标定的阈值不是生产标准**）：一条可见的物理导轨附近至少存在约 6 个独立价签实体，且沿轨道的相邻净间隔与价签宽度之比偏小、价签高度相对整图较小，或普通 API 在该区有可观察的漏排/重复/串位迹象。只有能从图像而非 GT 检出足量完整实体边界，且相对原 API 不退步，才把该区称为“可走本地密集分支”。图像密集但边界不可分则 uncertain，保留原 API/复核。

下一步先用开发图、5 张新人工图和普通/混合负例人工标注**区域级场景标签**，记录每张图的导轨数、每排实体数、间距/宽度分布、普通 API 漏排和本地可分性。现有 JSON 主要是价签框/价格，**没有经过确认的完整导轨上下边、硬负例类别和普通/密集区标签**；不能拿价签数量或当前探针路由结果冒充已标定分类器。按门店/批次留出样本，再计算 dense 召回、normal 误路由、mixed 区域覆盖、uncertain 与回退率。

## 问题二：先找导轨，怎样找方向与足量上下边界

**是，先找导轨，再沿导轨方向在受限走廊找价签框。**现有成功的 top_rail_slot_experiment.py 需要人工给 rail_top/rail_bottom；红圈试验还需人工给 x_min/x_max。这正是下一步要替换的输入，不是推翻原找框法。

1. 在图像边缘图中提取长线段或折线（例如 LSD/Hough）；按**局部位置、方向和横向覆盖**聚类，每条货架分别估计，不能把整图最长线当唯一导轨。避开门框、包装直线和照片边缘。
2. 在同一局部排内寻找有共同覆盖区间、上下间距合理、角度/透视一致且有像素梯度支持的**两条实体边**。输出上下边折线/四边形、有效横向范围、方向角、覆盖长度、拟合残差及 detected/inferred 来源。只有一条可见边时另一条是推断，必须标 uncertain，**不能算两界均已找到**。
3. 沿边界留安全余量取走廊；斜排按局部方向做仿射拉平，透视明显时分段或四边形拉平。用正逆变换保存每个候选的原图四角，最终需要标准 bbox 时取原图四角外接矩形，并防止归一化坐标误差。
4. 如果价签候选触及走廊上下界，就扩大余量重新检测；仍截断则拒绝该段本地流程。上下界是否“足量”不能靠裁条看起来够宽判断，而要报告每张人工价签被走廊完整覆盖的比例、两侧端点覆盖、截断数及多余包装/广告面积。

斜货架样本 新数据/45524464… 的上层图像长边斜率约 0.105，跨全图约 202 像素；单条水平裁带会截断端部。整排编号一次读价实验/新数据斜货架_仅拉平预览.jpg **只验证了单线斜率可做拉平预览**，尚未自动找成对上下边，也未完成本地框/读价验收。

## 问题三：本地画框能否准确泛化，并避开促销与包装

**当前不能宣称泛化。**顶部 17/17 是人工选带并在开发图上调过参数；红圈 6/6 也是人工选区的单次调用；固定参数到 45035165… 顶部只有 1/8。此前整排预览还出现空框、重叠框、漏框与半框风险。对原 API 已准确识别的外部区域，强行本地替换会回退。45035165… 的历史普通 API 为 8/8 定位且读价正确，另一轮最终提示词重跑只有 5/8，说明 API 本身也有运行/提示词波动；比较时必须保留版本与输入记录，不选最好一次代表稳定基线。

在检测出的导轨走廊内，**沿用** top_rail_slot_experiment.py 的多阈值轮廓提案，不先用整图矩形另造候选。把原图固定宽 45–115、高 30–65 像素的经验尺寸，改为根据该排图像尺度估计的相对宽高范围；逐候选检查四边支持、触带边、覆盖多张价签、相邻重叠、明显重复框及截断。NMS/合并只能基于真实边缘证据，不能用平均间距补齐缺口。几何找框要优先保召回，但“看似完整”的框也只能是待核验候选。

**导轨不是类别证明。**商品包装上的数字、促销牌、空卡槽和正常价签可在同一走廊。先用几何/版式及与导轨的附着位置排除明显非价签，再让按 ID 的 API 对每框返回 tag / promo / package / empty / uncertain、price/readable；真正的促销价签与广告牌应分开，促销是否单独输出需按业务口径确认，**不把它悄悄混入普通价签指标**。现有 rail_numbered_read.py 的提示词只返回 price/readable，**还不具备类别门禁**。类别冲突、半框、含两张、ID 缺失/重复或无法确定价签归属时拒识/复核，不凭高 price_confidence 强行入库。

逐排比较新旧方法的定位召回、precision、完整框率、半框/合框/重复率、包装及促销误框、价格精确率、ID 串位和拒识率。GT 未匹配框先人工核对是否真有遗漏，避免把缺标算误检。自动走本地分支应基于**图像可测的导轨与候选质量**，不能在推理时借人工 GT 判定哪排更好；开发图及外部图的 GT 只用于离线门槛校准。

## 失败探索：保留经验，不作为主线

2026-09-28 的 dense_structure_probe.py 是另起的**全图自适应阈值矩形 → 全局 Hough 方向 → 行聚类**诊断，**没有复用已有效的先圈导轨局部找框方法，也没有调用读价 API**。三个输出目录为 结构探针_开发图/、结构探针_外部45035165/、结构探针_斜货架45524464/，各自保存 structure_probe.json 和可视化。其 bands 是矩形外接范围投影，标作 inferred_boundary，**不是真实导轨上下实体边**；complete 只是启发式几何标签，不能证明价签完整或属于 tag 类。

## 接下来按什么顺序做

1. **冻结对照与标注需求。**锁定开发图 99 框/54/27、顶部 19 框/17 命中和红圈 7 框/6 命中/6 精确价格，不回写这些历史结果；记录 45035165… 的历史 API 顶部 8/8 与最终提示词重跑 5/8 两次对照，不能只选较好的一次。人工复核新数据的导轨上下边、角度、价签所属排和 tag/promo/package/empty 等硬负例；GT 看不清的小数标成不确定，不拿它训练确定价格阈值。
2. **只实现导轨优先的离线几何阶段。**对开发图和斜货架图分别输出每条导轨的上/下边、方向、共同覆盖区和 detected/inferred 标签及叠图；对无法定位两界的区域记录拒绝原因。与人工补标的导轨边比较方向、边界误差、端部覆盖和裁断率。此阶段**不改**原 API 框或价格。
3. **在通过门禁的走廊里复用局部找框。**拉平后调用原多阈值 detector，逐框保存完整性、重叠、半框/合框及坐标反变换，先在开发图复核顶部 17/17、红圈 6/6 能否保持；不能保持则回滚这一阶段，不用全图探针框填数。
4. **固定参数做外部盲测及语义排除。**在新数据和更多普通/混合图同口径比较原 API 与新候选，按排报告 IoU 0.3/0.5/0.7、完整框和非价签误框。先验证不会覆盖 45035165… 历史运行中正确的 8 个框，并分别报告新旧方案固定输入的结果，再对合格段试一次按 ID 的 Qwen3-VL-Plus 类别+读价；不合格段保留原流程或人工复核。
5. **再决定路由与生产。**按区域标定密集门槛及导轨/框质量门槛，记录普通误路由、密集漏路由、混合覆盖、回退率、每图 API 次数/耗时。需要多门店、不同角度与促销/包装硬负例的留出验证；现有少量样本和开发图成绩不足以确定生产阈值。

停止条件：若导轨上下边无法由图像独立确认、价签被截断、框间串位、包装/促销无法可靠排除或外部普通 API 正确区域被新方案覆盖，就**不启用该排本地框**。目前所有新工作均为离线验证；未修改生产链路，未证明泛化。

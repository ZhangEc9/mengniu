## 架构（已实现，`arbitration_loop.py`）

```
① 全图原 API（生产最终版提示词）          → 框+价              [view1]
② API 导轨框（自定义提示词）→ 实体验证
   → 走廊（Theil–Sen 定角、框/实体中心线二选一、x 范围∪实体范围）      [几何]
③ 走廊质量门禁（GT-free）：
   内点率≥0.45、内点残差≤0.35×中位实体高、内点数≥6、阶段B候选≥4
   通过 → 本地多阈值画框 + 2×编号条带 + 按ID读价（1次API/轨）        [view2]
   不通过 → 本地不出场（该排保留 view1）
   读后保护：可读价数量 < max(3, 50%框数) 的排整排退回 view1
④ 仲裁合并 v4：view2 先入列；view1 与 view2 重叠且同价→保留 view1，
   异价→用 view2（2×近距读数更可信）；无重叠的 view1 全保留；
   框里没价格一律不输出
```

## 已实锤的关键结论（不要重蹈覆辙）

1. **当前 Qwen3-VL-Plus：读数可信、定位不可信。**实锤证据：开发图 rail0 的 17 个"中心点" y 全部=375、x 等差 65——价格基本读对但坐标是均匀插值编造。历史佐证：全图画框 6/78、条带画框顶部全漏。**定位必须来自本地像素，模型只做读数器**（编号读价红圈 6/6）。
2. **导轨实体边没有强线**（低对比塑料），"先找线再配对"路线已死；**实体排聚类**（找价签样实体→聚排→拟合）是有效的走廊来源。
3. **走廊角度是主要短板**：框内实体拟合会被上方商品文字拉平（Theil–Sen 缓解但不根治），全图倾角兜底只救"全图一致微倾"，救不了 45524464 双排异角。斜排已按用户授权放弃。
4. **投影切分补洞收益有限**（+3 框 0 新命中）：轮廓漏掉的签本身图像证据弱。代码保留（`stageb_on_rails.py: projection_fill`）备用。
5. **真/假排的单一几何特征基本不可分**（真排 63 vs 假排 130 分布重叠）；`bot_edge_sup` 底边支持率曾入选门禁后被数据否决（误杀开发图最好排）。最终门禁只用内点特征。
6. **API 有明显 run-to-run 波动**（45035165 全图两次运行 m50 14↔22）：正式评测必须固定输入、报告波动区间。
7. **cv2.warpAffine 的 M 是前向映射**（src→dst，内部求逆）；**atan2 必须归一化到 [-90,90)**。这两个坑各吃掉半天。
